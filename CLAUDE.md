# Spread Joy Collective site: repo context for Claude sessions

Read this file first, then [SPEC.md](SPEC.md). SPEC.md is the **site-wide rulebook shared with teammates** (every page). This file is the **repo-specific context**: what is here, how to run it, and where the current code does not yet follow the spec.

## What this repo is

A local workspace for the Spread Joy Collective (nonprofit for individuals with disabilities and their families) website, which is **built and published on Squarespace 7.1**. The repo holds:

1. **A local mock of the site** (`index.html` and five other pages), generated by `build.py`, so the design can be viewed and tested in a local browser.
2. **Paste-ready Squarespace code** for the home page, in [home-page/](home-page/), generated from the same sources so the mock and Squarespace never drift apart.
3. **Tests** for both, and docs/specs.

Nothing is deployed from here. Squarespace is edited by hand (Code Injection plus Code Blocks). The repo stays local (no remote).

## Commands

```bash
python3 build.py                      # regenerates all pages, squarespace/ and home-page/
python3 -m http.server 8011           # local preview at http://localhost:8011/index.html (port 8000 is used by another process)
python3 -m unittest discover -s tests # markup, CSS and snippet tests
node --test tests/                    # logic tests (counter, ideas, scroll story, header, hearts)
```

Run both test suites before committing. Develop test-first (red, then green); a few bugs only showed up on real Squarespace pages, so each got a regression test.

## Squarespace facts learned the hard way

- Trial site `minnow-begonia-3l5p.squarespace.com`, page **"Home (new)"** (Not Linked) holds the test build. The real Home page is untouched. The trial site is only viewable inside the editor (the public URL redirects to login).
- JavaScript works in Code Injection and in Code Blocks (HTML mode) on this trial. Needs a Core, Plus or Advanced plan on a real site.
- Squarespace re-draws Code Block HTML after load, so scripts **must look elements up at event time**, never keep references (this broke the story and taps once).
- `offsetTop` is wrong inside Squarespace (use `getBoundingClientRect().top + scrollY`). `children` is a live HTMLCollection (no `.filter`).
- The editor view runs scripts unreliably; test in **Preview** or the saved page. Safe Mode turns custom code off.
- A browser with forced dark mode turned the page black until `:root { color-scheme: only light }` was added.
- Squarespace gives headings their own colour and font, so text that must be white uses `!important` and headings get `font-family: inherit`.
- Squarespace's header sits on top of the first section; the hero has extra top padding for it.
- Images must be uploaded to Squarespace (Code Blocks cannot read repo files). Uploaded via an Image block; addresses are in `home-page/image-urls.json`.
- Pushing code to the trial site was done by setting editor contents (CodeMirror) from the generated files. The generated files are what the user pastes.

## SPEC.md versus the current code: known gaps

SPEC.md was adopted **after** the home page was built (and was updated on 2026-10-17 with the Code Block lessons in §8 and the variables read from the trial site in §9). The home page code **does not yet comply** with these rules. Do not treat the current code as the standard; when touching the home page, either fix the gap or flag it to the owner. Do not quietly pick a side.

| SPEC.md rule | Current home-page code |

| §3/§6: `font-family: inherit`, no font names, no third-party fonts | Loads League Spartan and Oooh Baby from Google Fonts and names them |
| §4/§6: header, nav, footer, Give button are native Squarespace, not restyled from code | `1-header-injection.html` restyles `#header` (white, yellow line, logo, menu, button) site-wide, and `6-footer-block.html` rebuilds the footer in code |

| §6: no site-wide CSS inside code blocks | Header paste holds site-wide header, color-scheme and layout overrides |
